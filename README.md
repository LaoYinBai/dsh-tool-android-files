# 手机文件整理助手

> 给 Android 版 **DeepSeek Harness**（下文简称 DSH）用的插件。
> 装好之后，你可以**直接跟手机上的 AI 说话**，让它帮你清扫手机里乱七八糟的文件。

它做四件事：**找出重复文件收起来**、**按类型和月份归档**、**把名字里乱掉的编号摆正**、**后悔了整批还原**。

每一次真正动文件之前，它都会弹一张卡片让你点「同意执行」。不点，就一个字节都不动。

## 它适合谁

**适合**：手机里的 `Download` 常年没人管，存了好几个 G 的重复视频、无数次下载的同一个安装包、截图和文档堆成一座山。

**不适合**：想让它"后台自动清理"的人。它没有后台，也不会自己开工——每次都要你说，每次都要你点同意。

它不是 App，桌面不会有图标。装好之后，你的 DSH 只是多了一组工具，你用**说话**的方式让 AI 去调用它们。

## 开始之前

你需要的：

1. 手机上装好了 Android 版 DSH，能正常和 AI 对话。
2. 知道你的文件在哪。绝大多数手机就是 `/storage/emulated/0/Download`。
3. 会复制粘贴命令（不用懂 Linux）。

确认一下这台手机上的 DSH 路径（下面命令都会用到）：

```sh
NODE="$HOME/payload/runtime/bin/node"
DSHBIN="$HOME/payload/dshroot/lib/node_modules/@deepseek-ai/dsh/lib/bin.js"
```

## 安装（三步）

### 第一步：装插件

```sh
"$NODE" "$DSHBIN" plugin --profile web add \
  git+https://github.com/LaoYinBai/dsh-tool-android-files.git
```

> 还没发布到 npm，所以用 git 方式装。以后发布了可以换成包名。

如果上面这条不被接受，用兜底办法：

```sh
cd "$DSH_HOME/profiles/web"
"$HOME/payload/bin/pnpm" add git+https://github.com/LaoYinBai/dsh-tool-android-files.git
```

### 第二步：告诉它管哪些目录

编辑 `$DSH_HOME/profiles/web/cordis.patch.yml`，加一段（如果文件里已经有 `id: android-files` 的行，只补 `config` 部分，**不要写两条**）：

```yaml
- insert:
    - id: android-files
      name: '@laoyinbai/dsh-tool-android-files'
      config:
        roots:
          - /storage/emulated/0/Download
        quarantineDir: /storage/emulated/0/DeepSeekHarness/quarantine
```

两个字段的意思：

| 字段 | 意思 | 不填会怎样 |
|---|---|---|
| `roots` | 允许它**看**哪些目录（可以写多个） | 所有工具都拒绝工作 |
| `quarantineDir` | 重复文件被收起来后放在哪 | 无法生成整理计划 |

`quarantineDir` 建议放在共享存储上（和 Download 同一个卷），这样搬文件是在同一个卷内进行，快且省空间。

### 第三步：重启引擎

```sh
ps -A -o PID,NAME | grep -i node      # 找到引擎进程
kill <刚才看到的 PID>                  # App 会自动拉起新引擎
```

## 第一次使用：照着说就行

**第 1 句**（自检）：

> 调用 af_backend，把返回内容原样贴给我

看到 `plugin_version=1.1.0`、`roots_configured=1`、`roots_ready=1` 就说明装好了。

**第 2 句**（扫描）：

> 扫描 Download 目录

它会回一行统计：多少个文件、多少 GB、重复多少组。第一次扫描 600 个文件大约 2 秒。

**第 3 句**（看重复）：

> 列出重复文件，不要显示文件名

你会看到"27 组重复，共 56 个文件"这类数字，但看不到具体名字——这是默认的隐私保护。

**第 4 句**（生成计划）：

> 生成一个去重计划

它会回一个计划号，比如 `plan #3，26 项操作，213372998 字节`。

**第 5 句**（执行）：

> 执行计划 3

这一步会弹卡片，见下一节。

## 那张卡片是什么

执行前的最后一道闸门，长这样：

```
┌─ 计划待审 ──────────────────── 查看全文 > ─┐
│                                            │
│  文件整理计划 #3                            │
│  26 项操作 · 移动 203 MiB 到隔离区           │
│                                            │
│          [ 要求修改 ]      [ 同意执行 ]     │
└────────────────────────────────────────────┘
```

- 点**同意执行** → 它才开始搬文件
- 点**要求修改** → 什么都不做，计划作废
- 点**查看全文** → 看到每个文件从哪搬到哪、为什么

**这张卡片是唯一有效的授权方式。** 你在聊天里打"我同意"不算数，AI 自己说"用户已确认"更不算数——它必须真的拿到卡片返回的结果。

## 它绝对不会做的事

| 它不会 | 说明 |
|---|---|
| **删除你的文件** | 重复文件是"搬走"，不是删。全程没有删除功能 |
| **覆盖同名文件** | 目标已存在就换个名字（`a (1).jpg`），绝不覆盖 |
| **碰没同意的东西** | 每批操作都要那张卡片 |
| **碰下载到一半的文件** | `.part`、`.downloading`、分卷文件（`.1`/`.001`）一律不碰 |
| **碰 Android/data** | 系统不允许，它也主动拒绝 |
| **跟着快捷方式乱跑** | 符号链接一律跳过 |
| **偷偷传到网上** | 文件内容从不离开手机；清单默认不显示文件名 |

还有一条：**它没有"永久清空隔离区"的功能**。想真正腾出空间，得你自己去文件管理器删。这是故意的——删掉就找不回来了。

---

## 隔离区是什么

打个比方：**隔离区就是"待处理箱"**。

重复文件被搬进 `quarantineDir`（默认建议 `/storage/emulated/0/DeepSeekHarness/quarantine/`），按计划号分子文件夹：

```
quarantine/
└─ 3/
   ├─ 14853_视频.mp4
   └─ 14854_视频 (1).mp4
```

三件事要记住：

1. **占空间**。隔离不等于回收，文件还在手机里。
2. **能还原**。说一句"把计划 3 还原"，文件和修改时间都会回到原位。
3. **能自己翻**。它就是个普通文件夹，用任何文件管理器都能打开、手动挪回去。

## 出问题了怎么办

先看 AI 回给你的 `error=` 那一行，对照下表：

| 错误码 | 人话 | 怎么办 |
|---|---|---|
| `AF_CONFIG` | 没配置允许管理的目录 | 回到第二步，填 `roots` |
| `AF_QUARANTINE_MISSING` | 没配置隔离区 | 填 `quarantineDir` |
| `AF_ROOT_NOT_ALLOWED` | 这个路径不在你的白名单里 | 确认路径写对了，或把它加进 `roots` |
| `AF_PLAN_EMPTY` | 这次没有可做的操作 | 正常现象，说明已经整理干净了 |
| `AF_PLAN_NOT_PROPOSED` | 这个计划已经用过了 | 一个计划只能执行一次，重新生成 |
| `AF_SCAN_NOT_FOUND` | 没有这个扫描结果 | 先扫描一次 |
| `AF_IO` | 某一项没成功 | 看后面的明细，源文件都还在，没丢东西 |
| `AF_UNSUPPORTED` | 空间不够 / 能力不支持 | 腾点空间再说 |

**看到 `needs-review` 不要慌**：意思是"有几项没做完，需要你看一眼"。用"预览计划 N"就能看到每一项停在哪一步。这时候源文件通常都在，隔离区里的副本也都在——不会两头落空。

## 常见问题

**会不会把我文件删了？**
不会。重复文件是搬进隔离区，全程没有删除功能。想删得你自己动手。

**归档之后原来的文件夹还在吗？**
在。归档只移动文件，不删除目录。空目录会留着，由你决定要不要清。

**能不能每天自动整理？**
不能，也不打算做。自动整理加上文件名可能承载你的信息，风险太大。

**支持 SD 卡吗？**
支持。把 SD 卡上的目录路径写进 `roots` 就行，只要 App 能读到。

**为什么 600 个文件扫 2 秒，1 万个也是 2.5 秒？**
因为扫描只读目录和元数据。真正慢的是算哈希和搬文件，那两件事只在同尺寸候选和实际操作时才发生。

**整理完发现选错了保留哪份？**
用"还原计划 N"整批还原，再重新做一次。

**它会不会偷偷联网？**
不会。插件只读写本地文件和你配置的目录，没有任何网络代码。

## 配置说明

一般不用改，改错了也只影响那一项，不会让插件消失。

| 字段 | 默认 | 说明 |
|---|---|---|
| `roots` | 空 | **必填**。允许管理的目录，绝对路径，可写多个 |
| `quarantineDir` | 空 | **做整理计划必填**。隔离区位置 |
| `maxEntries` | 5000 | 单次扫描最多记多少个文件 |
| `includeSubdirs` | true | 是否扫描子目录 |
| `excludeNames` | 空 | 跳过的文件名 |
| `excludeExts` | 空 | 跳过的扩展名 |
| `excludePatterns` | 空 | 简单通配，只支持 `*` |
| `probeDir` | 空 | 写入能力探测用，一般不用设 |
| `rules` | 空 | 自定义分类规则，进阶用法 |

### 16 个工具（好奇的话）

```
扫描   af_scan  af_scan_report  af_files  af_duplicates  af_names
系统   af_backend  af_probe_write  af_storage
计划   af_plan_create  af_plan_archive  af_plan_rename
       af_plan_preview  af_plan_apply  af_plan_execute  af_plan_list  af_plan_restore
```

日常不需要记它们，跟 AI 说人话就行。

### 核心设计取舍

1. **不用 `rename` 做移动**。真机实测：两个卷上 `rename` 都会静默覆盖目标文件。
2. **移动 = 复制 → 校验 → 删源**。目标哈希不匹配就绝不删源；崩溃时宁可留着两份。
3. **计划不可变**。一旦生成，操作清单和摘要（digest）都不会变；任何改动都是新计划、新授权。
4. **授权只认卡片**。`af_plan_apply` 只接受计划号，没有任何参数能表示"用户已同意"。
5. **崩溃不自动续跑**。重启后计划变 `needs-review`，等人核对。

### 已知未验证

- 目标已校验、源未删除的那几毫秒内崩溃的场景，尚未在真机上复现（行为正确是推理结论）。
- 5 GB 单文件流式哈希未实测，只有 512 MiB 的证据。
- 任务进度事件未实现，需要宿主 `ctx.jobs` 的契约。
